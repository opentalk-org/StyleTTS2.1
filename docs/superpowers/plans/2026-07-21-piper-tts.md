# Piper TTS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add catalog-backed Piper voice downloads and batched multilingual synthesis with the same voice fan-out and output contracts as the existing TTS nodes.

**Architecture:** A typed Piper catalog module reads the public `voices.json`, filters voices, and persists each selected ONNX/config pair as a checkpoint folder. Piper voice payloads carry their checkpoint reference; a dedicated synthesis node groups expanded requests by model so each voice loads once per incoming batch.

**Tech Stack:** Python 3.12, Pydantic, shared SQLAlchemy asset CRUD, piper-tts, NumPy, runflow node runtime, React/TypeScript schema-driven workflow editor.

## Global Constraints

- Run project commands only through `nix develop --command ...`.
- Access checkpoint folders only through `src/shared/db/assets/crud.py` public functions.
- Keep `src/runflow` domain-agnostic.
- Each Piper model is exactly one voice checkpoint containing `.onnx` and `.onnx.json`.
- Synthesis never silently downloads a model.
- Keep every file below 300 lines and every folder below 16 files.
- Temporary tests must be removed before completion.
